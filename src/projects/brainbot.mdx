## Introduction

BrainBot was a full-stack project built around a simple idea:

Learning slang shouldn’t feel like reading a dictionary.

Instead of static definitions, we designed a platform that feels closer to a live learning experience, combining structured lessons, social features, games, and an in-app assistant.

The goal was to make learning interactive, social, and replayable, rather than something users do once and forget.

---

## Product Inspiration

The design of BrainBot was influenced by two main ideas:

- The structured learning progression seen in platforms like Duolingo  
- The community-driven content model of Urban Dictionary  

From Duolingo, we adopted the concept of a **learning tree**, where users progress through lessons in a guided and incremental way. This helps structure learning instead of leaving it completely open-ended.

From Urban Dictionary, we took inspiration for a **community contribution system**, where users can submit slang entries, including definitions, examples, and origins.

To ensure content quality, we implemented a **moderation workflow**:

- Users can submit new slang entries  
- Moderators review and approve submissions  
- Only approved entries are published to the main dictionary  

This balances openness with reliability, preventing low-quality or incorrect content from entering the system.

---

## Product Vision

Most slang platforms are passive:

- Search a word  
- Read the meaning  
- Leave  

We wanted something more engaging.

BrainBot was designed around five core experiences:

- Learn — structured lessons and progression  
- Explore — community-driven slang dictionary  
- Play — games like Slangle and quizzes  
- Socialize — friends, rankings, and competition  
- Assist — an AI assistant for contextual help  

The result is a system where users don’t just consume content, but continuously interact with it.

## System Architecture

The system is split into two main components:

### Frontend
- React (Vite)
- React Router
- UI libraries (Lottie, Lucide)

### Backend
- Java 21
- Spring Boot
- Spring Web MVC
- Spring Data JPA
- PostgreSQL / H2

The backend was built using Spring Boot, exposing RESTful APIs that handled all application logic, including user progress, dictionary data, moderation workflows, and gameplay interactions.

For deployment:

- AWS Kubernetes hosted the application  
- Nginx reverse proxy handled routing in containerized environments  
- Backend services were kept internal while the frontend remained publicly accessible
