## Introduction

Art Studio Cafe is a microservice-based web platform designed around a complete user journey:

Discover activities -> book time slots -> add food and drinks -> complete payment -> receive confirmations.

Instead of building a monolithic system, this project was designed to explore how a real-world application can be decomposed into independent services, each responsible for a specific business capability.

The system also includes an AI-assisted recommendation flow to guide users toward activities that match their preferences.

---

## System Overview

The platform is structured as a full-stack microservices system with:

- React frontend  
- Kong API Gateway as the only public entrypoint  
- Multiple FastAPI microservices and composite services  
- RabbitMQ for asynchronous communication  
- Postgres with database-per-service ownership  

At a high level, the user flow is:

- Browse or discover activities  
- Select a valid booking slot  
- Add food or drinks  
- Submit payment  
- Receive booking confirmation  
- Manage bookings  

---

## Architecture

### Public Request Flow

Frontend (React)  
→ Kong API Gateway  
→ Downstream services and composite services  

Kong acts as the single entrypoint, routing requests to the appropriate services.

---

### Microservice Design

The system is decomposed into:

- Core services (user, activity, menu, food order, quiz)  
- Composite services:
  - make-booking-composite-service  
  - ai-recommender-composite-service  
- Wrappers for external integrations:
  - payment-wrapper  
  - ai-recommendation-wrapper  
- Notification service for email delivery  

Each service owns its own database, following a database-per-service pattern.

---

### Event-Driven Communication

RabbitMQ is used for asynchronous workflows.

Example:

- Booking is created  
- Event is published  
- notification-service consumes the event  
- Confirmation email is sent  

This decouples booking logic from notification delivery and improves system resilience.

## Challenges

### 1. Managing Service Complexity

Compared to monolithic systems, microservices introduced:

- More moving parts  
- Inter-service communication challenges  
- Increased debugging complexity  

Understanding how services interact was one of the main challenges.

---

### 2. Orchestrating Distributed Workflows

The booking process required coordination across multiple services.

Handling:

- Partial failures  
- Ordering of operations  
- Data consistency  

was more complex than a single-database system.

---

### 3. Asynchronous Communication

Using RabbitMQ introduced new considerations:

- Event design  
- Message reliability  
- Debugging asynchronous flows  

While powerful, it required a different mindset compared to synchronous APIs.

---

### 4. Deployment Complexity

Deploying multiple services on EC2 required:

- Managing containers  
- Handling networking between services  
- Debugging issues that did not appear locally
